# 用 Codex 适配自己的显示器

目标是复用方法与结构，在你自己的 Mac、显示器和连接方式上验证实现。当前代码里的三星型号编号、0–100 范围和通信时序，不能当成通用配置。

## 1. 识别与只读探测

记录显示器型号、连接线、转接器/扩展坞、macOS 版本、HDR 状态、实体菜单中的 DDC/CI 开关。试验期间先退出其他自动调亮度工具，避免相互覆盖。

```sh
# 型号识别，不输出序列号或 UUID。需要 Swift 工具链。
swift tools/display_info.swift

# 只读取亮度。Python 3，限 macOS / Apple Silicon IOAVService 路径。
python3 tools/ddc_probe.py --feature 0x10

# 可选：读取显示器声明的能力字符串。
python3 tools/ddc_probe.py --feature 0x10 --capabilities
```

DDC 查询仍会向总线发送查询报文；“只读”指不发送 Set VCP、重置、输入切换或电源命令。工具会逐个查询外接 DDC 服务；应用的写入路径则要求恰好一个外接服务。

如果亮度不可读、回复校验失败或值域不合理，先解决通信问题。更换连接线、扩展坞或输入端口后也应重新验证。

## 2. 可恢复的亮度试验

先确认亮度原值和最大值，选择比当前值略高、自己可接受的试验值，不要直接沿用 100。亮度试验工具当前只接受 0–100；其他范围应先适配工具和原生代码。

下列命令会实际改变硬件亮度；将 `40` 换成确认过的试验值：

```sh
python3 tools/ddc_brightness_trial.py \
  --brightness 40 --hold-seconds 5 \
  --report local/brightness-trial.json
```

工具要求恰好一个外接 DDC 服务；先记录原值，再暂时写入、读回、恢复并记录结果。试验期间不要手动调整亮度或切换预设。

`finally` 和信号处理会尽量执行恢复；强制杀进程、拔线或断电仍可能中断恢复。保留原始值，准备通过实体菜单手动恢复。未确认恢复成功前，不启动自动化。报告放在被 Git 忽略的 `local/` 下。

## 3. 修改适配点

| 文件 | 核对内容 |
| --- | --- |
| `NativeApp/Sources/DDC.swift` | `TargetDisplay.connected()` 的厂商/型号、目标唯一性、外接服务绑定、亮度最大值、校验和、等待时序、读回验证 |
| `NativeApp/Sources/App.swift` | 固定观影值 100、初始日常值 30、捕获原值、`restorePending`、失败恢复、退出时等待写入完成 |
| `NativeApp/Sources/Activity.swift` | 应用 bundle ID、前台窗口、目标屏上的全屏判断 |
| `BrowserExtension/content.js` | 视频元素、全屏容器、iframe、开放 Shadow DOM |
| `BrowserExtension/activity.mjs` | 活跃标签、窗口焦点、帧状态和过期信号 |
| `NativeApp/Resources/使用说明.html` | 适配后的型号、亮度和限制 |

不要仅删除型号保护以“兼容所有显示器”。要支持多屏，先实现显示器与 DDC 服务的可靠绑定；当前“一个目标型号 + 一个外接服务”的策略不足以支持一般多屏场景。

`BrowserExtension/manifest.json` 的 `key` 是公开公钥，用于固定扩展 ID。若 fork 时更换它，也要同步更新 `NativeApp/Resources/extension-id.txt`。每个浏览器实例的认证令牌在本机配对时单独生成。

## 4. 验收恢复行为

按 README 构建和运行逻辑检查，随后在实际硬件上验证：

- 窗口播放保持日常亮度；目标屏上的全屏视频变亮。
- 退出全屏、切换应用、关闭自动调整后恢复。
- 全屏暂停保持观影亮度；正常退出工具后恢复。
- 睡眠唤醒、断开重连后行为合理；DDC 出错时有提示。
- 重开工具可恢复未完成的状态；多个外接服务存在时拒绝写错屏。
- Chrome、Dia 各自配对；普通浏览器全屏但没有视频时不变亮。

逻辑测试不能代替实际画面、实体菜单和硬件读回。亮度变化也不能证明原生预设已切换。
