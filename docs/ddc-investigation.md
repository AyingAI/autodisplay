# DDC 调查：亮度与 HDR 预设是两件事

以下是 2026-10-21 至 2026-10-22 在一套 Apple Silicon Mac 与三星 LS27A600U 连接上的观察。仅保留可复用结论；设备 UUID、注册表实例 ID、逐次报告与本机路径不随仓库公开。

## 实机观察

DDC/CI 通信可用，可读取亮度、对比度、颜色参数及通用模式码。屏幕在系统 HDR 开启时工作于 2560×1440、75 Hz；应用不设置这些参数。

使用者在实体菜单中手动切换并确认名称后，读取结果为：

| 控制项 | 个人设定 HDR | 标准 HDR |
| --- | ---: | ---: |
| `0x10` 亮度 | 30 | 100 |
| `0x12` 对比度 | 75 | 75 |
| `0x14` 颜色预设码 | 4 | 4 |
| `0xDC` 通用模式码 | 2 | 2 |

对照采样包含 48 个标准或厂商扩展项；成功回复的状态与值中，只有亮度不同。没有向厂商扩展项写入，也没有据此推断所有未公开协议都不支持预设切换。

`0xDC` 曾完成 `2 → 3 → 2` 的写入与读回，但不随这两个 HDR 预设变化。因此不能把“代码写进去”解释为“影院或标准 HDR 已开启”。标准名称、声明的能力值和真实实体菜单，需要分别核对。

## 最后采用的实现

在“个人设定 HDR”下写入 `0x10=100`，画面变亮；使用者确认实体菜单仍是“个人设定 HDR”。恢复 30 后，检查的对比度、颜色参数和通用模式码与原值一致。

因此应用只自动控制亮度，不再把原生 HDR 预设切换列为已实现功能。全屏前保存原值，退出时恢复；失败和退出过程中也保留恢复逻辑。Chrome、Dia、IINA 的全屏调亮与退出恢复均经过使用者实测确认。

## 不应外推的部分

未验证 HDR 动态、关闭 HDR 后的普通预设、多屏绑定、其他型号、Intel Mac 或所有连接方式。同型号经不同扩展坞、输入端口连接，也需重新验证。系统 HDR / 参考模式 API 与显示器实体菜单的厂商预设不是同一层控制。

参考 [AppleSiliconDDC](https://github.com/waydabber/AppleSiliconDDC) 和 [m1ddc](https://github.com/waydabber/m1ddc) 核对接口与传输；本型号结论以实际对照为准。
